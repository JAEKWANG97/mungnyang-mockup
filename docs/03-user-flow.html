핵심 사용자 흐름

전체 MVP 흐름

업로드자 사진 등록
→ 운영자 검토
→ 승인 사진이 발송 후보가 됨
→ 수신자에게 정기 이메일 발송
→ 수신자가 버튼 반응
→ 업로드자는 익명 누적 반응 확인

이 흐름 밖의 기능은 MVP에서 보류합니다.

수신자 흐름

상황

수신자는 귀여운 동물 사진을 보고 싶지만, SNS 피드를 계속 보고 싶지는 않습니다.

목표

아침 또는 정해진 시간에 동물 사진 한 장을 이메일로 받고, 부담 없이 반응하고 끝냅니다.

흐름

랜딩 페이지 방문
→ 서비스 설명 확인
→ 이메일 입력
→ 수신 동의 체크
→ 발송 주기 확인
→ 신청 완료
→ 정기 이메일 수신
→ 사진 확인
→ 버튼 반응 클릭
→ 종료

UX 원칙

  • 수신 신청은 짧아야 합니다.
  • 앱 안에서 오래 머물게 만들지 않습니다.
  • 이메일 안의 반응도 1클릭에 가깝게 만듭니다.
  • 반응 후 “다른 사진 더 보기”를 강하게 유도하지 않습니다.

업로드자 흐름

상황

업로드자는 귀여운 동물 사진을 누군가에게 보여주고 싶지만, SNS처럼 평가받고 싶지는 않습니다.

목표

사진 한 장을 가볍게 등록하고, 누군가가 받았을 때의 익명 반응만 확인합니다.

흐름

업로드 페이지 방문
→ 사진 선택
→ 짧은 설명 입력
→ 직접 촬영/사용권 확인
→ 콘텐츠 정책 동의
→ 등록
→ 검토 대기
→ 승인 또는 반려 확인
→ 발송 후 익명 반응 확인

UX 원칙

  • 업로드는 “자랑”보다 “우편 보내기” 느낌이어야 합니다.
  • 반응 확인은 경쟁 지표처럼 보이면 안 됩니다.
  • “몇 위”, “인기”, “좋아요 랭킹” 같은 표현을 쓰지 않습니다.

운영자 흐름

상황

운영자는 서비스가 귀엽고 안전한 상태를 유지해야 합니다.

목표

업로드 사진을 검토하고, 발송 후보를 관리하고, 신고/수신거부/발송 실패를 처리합니다.

흐름

운영자 페이지 접속
→ 검토 대기 사진 확인
→ 콘텐츠 정책 기준으로 승인/반려/숨김
→ 승인 사진 발송 후보 등록
→ 발송 전 이메일 미리보기 확인
→ 테스트 발송 또는 실제 발송 승인
→ 발송 결과 확인
→ 신고 사진 처리

UX 원칙

  • 운영자는 발송 전 마지막 승인 지점이어야 합니다.
  • 신고된 이미지는 즉시 운영자 검토 대상으로 보여야 합니다.
  • 자동 삭제보다 임시 숨김과 수동 판단을 우선합니다.

이메일 흐름

제목: 오늘의 멍냥우편이 도착했어요
상단: 짧은 인사
본문: 동물 사진 1장
설명: 업로드자가 남긴 짧은 문장
반응: 버튼 3~5개
하단: 수신거부 / 신고 / 서비스 안내

이메일 톤은 조용하고 따뜻해야 하며, 광고처럼 보이면 안 됩니다.

피해야 할 문구:

  • 오늘의 인기 사진
  • 베스트 사진
  • 가장 많이 사랑받은 사진
  • 지금 앱에서 더 보기
  • 친구를 초대하면 보상

추천 문구:

  • 오늘 아침 작은 귀여움이 도착했어요.
  • 누군가가 보내온 멍냥우편입니다.
  • 마음에 들었다면 가볍게 반응을 남겨주세요.

  • 수신 신청 페이지

  • 이메일 템플릿

2순위

  • 반응 완료 페이지
  • 수신거부 페이지
  • 업로드 상태 페이지
  • 발송 결과 페이지

3순위

  • 익명 반응 요약 페이지
  • 신고 관리 페이지
  • 지표 대시보드
